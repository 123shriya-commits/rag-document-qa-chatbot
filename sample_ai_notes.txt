Retrieval-Augmented Generation (RAG) Notes

RAG is a technique that combines information retrieval with text generation. Instead of relying only on
what a language model learned during training, RAG retrieves relevant chunks of text from an external
knowledge base at query time and feeds them to the model as context. This allows the model to answer
questions about documents it has never seen before, and reduces hallucination because answers are
grounded in retrieved evidence.

A typical RAG pipeline has four stages: document ingestion, chunking, embedding and indexing, and
retrieval plus generation. During ingestion, raw documents such as PDFs or web pages are converted into
plain text. During chunking, the text is split into smaller overlapping segments so that no single chunk
is too large for the embedding model, and important context is not lost at chunk boundaries.

Embeddings are numerical vector representations of text that capture semantic meaning. Sentence
embedding models such as all-MiniLM-L6-v2 convert each chunk into a fixed-length vector. These vectors
are stored in a vector database or a vector index such as FAISS, which allows fast similarity search
even across millions of chunks.

When a user asks a question, the question itself is embedded into the same vector space, and the
index is searched for the chunks whose embeddings are closest to the question's embedding. These
retrieved chunks are then combined with the original question into a single prompt, which is passed to
a text generation model. The generation model produces an answer that is grounded in the retrieved
context rather than purely in its own training data.

Common use cases for RAG include customer support chatbots that answer questions from a company's
documentation, internal knowledge assistants for employees, legal or medical document question
answering, and personal assistants that can answer questions about a user's own files.

Popular open-source components for building a RAG system include sentence-transformers for embeddings,
FAISS or Chroma for vector storage, and open models such as Flan-T5, Llama, or Mistral for generation.
